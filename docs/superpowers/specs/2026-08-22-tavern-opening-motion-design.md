# Tavern 角色卡背景与开场切换动效设计

日期：2026-08-22  
状态：已确认，待实施

## 目标

在不改变 RikkaHub 原生顶部栏、状态栏和输入栏的前提下，为酒馆角色卡背景和多开场白切换增加克制、自然的动态反馈。

成功标准：

- 有角色卡背景时，画面具有缓慢的景深呼吸感，但不会分散阅读注意力。
- 点击左右按钮或横向滑动切换开场白时，内容按切换方向平滑进入。
- 动效不重建 WebView、不改变滚动位置、不阻塞连续切换。
- Android 系统关闭动画或 WebView 命中 `prefers-reduced-motion: reduce` 时停用位移与缩放。

## 方案选择

采用“原生背景层 + WebView 内容层”的双层协同方案。

角色背景继续由现有 Compose `Background` 链路绘制，仅在该层加入环境动效。开场白继续由单一 `TavernConversationWebView` 渲染，在 HTML 文档内部完成方向转场。两层不共享动画时钟，也不新增跨桥动画 RPC，避免把装饰效果耦合进会话协议。

未采用的方案：

- 纯 WebView 动效无法覆盖应用原生背景，层次感不足。
- 全屏 Compose 转场会牵动 WebView 容器，可能引入闪烁、状态丢失和触摸卡顿。

## 视觉语言

动效的主题是“画卷轻启”，不是粒子特效或强烈镜头运动。

### 背景环境动效

- 只在存在有效角色卡背景图片时启用。
- 单次周期为 14 秒，往返循环，不在周期末跳变。
- 缩放范围约为 `1.015 → 1.045`。
- 水平与垂直位移不超过容器短边的 1.2%，位移方向与缩放错峰，避免机械式同步。
- 现有遮罩、渐变和前景可读性保持不变；不改变图片裁切策略。
- 页面不可见或系统要求减少动态效果时，不启动无限动画。

### 开场白方向转场

- 向下一条开场切换：新内容从右侧约 18dp 等效距离进入。
- 向上一条开场切换：新内容从左侧约 18dp 等效距离进入。
- 动画时长 220ms，使用减速曲线；透明度 `0.35 → 1`，缩放 `0.985 → 1`。
- 首次加载、普通消息刷新、流式更新和状态变量更新不播放开场切换动画。
- 计数器与开场卡片一起进入，左右操作按钮保持固定，避免点击目标移动。
- 连续快速切换时，旧 DOM 随现有 `replaceChildren` 流程移除，最新内容立即成为唯一动画目标。

## 架构与数据流

### Compose 背景层

`Background.kt` 根据背景是否存在及系统动画比例选择静态或动态绘制参数。动态参数只作用于图片绘制层的缩放和偏移，不作用于 TopBar、StatusHudBar、WebView 或 ChatInput。

为便于单元测试，将启用条件和数值范围放入小型、无 Compose 状态依赖的 motion policy。Composable 只负责把 policy 转换为动画值。

### Tavern WebView 层

`tavern-conversation.html` 在应用新快照前保存旧的 `openingSwipe.index`。只有以下条件全部成立时才计算方向并为新的开场消息增加一次性进入类：

1. 旧、新快照都包含 `openingSwipe`；
2. 新旧索引不同；
3. 当前渲染目标是最后一个 assistant 开场节点；
4. 用户未要求减少动态效果。

方向由索引差确定，不扩展 `TAVERN_CHAT_PROTOCOL_VERSION`，也不要求 Kotlin 桥传递临时动画状态。动画结束后移除一次性类，DOM 保持稳定。

## 交互与异常处理

- 按钮点击和横向手势继续走同一个 `selectGreeting` 桥方法，因此方向反馈一致。
- 候选尚未 ready 时沿用现有 loading 表现；成功返回新快照后才播放进入动画。
- 加载失败时保留当前已渲染内容，不提前执行退出动画，避免白屏。
- 纵向滚动优先级、`touch-action: pan-y` 和现有横滑阈值保持不变。
- 切换后不主动抢焦点，不唤起键盘，不移动原生输入栏。

## 无障碍与性能

- WebView 使用 `@media (prefers-reduced-motion: reduce)` 禁用开场 transition/animation。
- Compose 尊重系统动画比例；比例为零时使用完全静态的背景参数。
- 背景动画不分配新位图、不重复解码图片、不触发 WebView 重载。
- 只允许一个背景无限动画和一个短时开场进入动画，不添加模糊滤镜、粒子层或 JavaScript 定时器。

## 测试策略

按照 TDD 实施：

1. 为背景 motion policy 添加失败测试，覆盖有图、无图和减少动态效果三种状态。
2. 为 HTML 文档添加失败测试，要求存在方向推断、一次性动画类、220ms 参数和 reduced-motion 降级。
3. 增加快速连续切换的文档级断言，确认新渲染会替换旧动画目标。
4. 运行相关 JVM 测试、完整 `:app:testDebugUnitTest` 和 `:app:assembleDebug`。
5. 安装 arm64 Debug APK，在 MNA-AL00 上验证背景、按钮切换、横滑切换、纵向滚动和原生输入栏稳定性，并检查 logcat 无 FATAL。

## 验收清单

- 角色卡背景可见且缓慢运动，无跳帧式周期重置。
- `1 / 5 → 2 / 5` 从右侧进入，反向切换从左侧进入。
- 首次打开对话不出现多余横向滑入。
- 连续快速点击后只显示最终选中的开场白。
- 上下滚动不被横向动画或手势识别阻塞。
- 原生顶部栏、StatusHudBar 和 ChatInput 不参与动画。
- 系统减少动态效果时背景与开场均静态更新。
