# Tavern 自适应渲染宿主设计

日期：2026-08-23  
状态：用户已确认

## 1. 目标

在保留 RikkaHub 原生顶部栏、消息结构和输入栏的前提下，为角色开场、状态栏和对话中的酒馆内容提供统一、完整的自适应渲染系统。

系统必须优先保留角色卡作者提供的 HTML、CSS、脚本、图片、动画和交互；只有当卡片出现不可用状态时，宿主才执行通用修复。修复不得依赖角色卡名称、固定选择器或单张卡片的数据。

本设计重点解决：

- 状态栏有效显示面积不足，人物图片和长内容被固定高度裁切。
- `vh` 在 WebView 初始零高度阶段计算错误，导致设置等固定弹窗无法使用。
- WebView 横向手势被外层 Compose 容器截走，卡片轮播收不到完整触摸序列。
- 开场、状态栏和对话 HTML 使用不同策略，导致同一角色卡表现不一致。
- 远程图片失败后永久空白，缺少缓存、重试和可理解的降级。
- 整文档重载、观察器抖动和离屏动画造成额外重排、耗电与滚动卡顿。

## 2. 已确认的产品方向

### 2.1 自适应宿主

保留卡片原始风格与运行逻辑。宿主只处理越界、零高度、触摸冲突、资源失败和运行时异常，并提供安全降级。

不采用以下方案：

- 完全不干预卡片：无法保证复杂卡片在 Android WebView 中可操作。
- 将所有卡片原生重绘：会丢失作者设计的 HTML、CSS、动画、设置和专属交互。
- 默认独立全屏浏览器：会破坏原生聊天上下文与输入体验，并增加 WebView 生命周期成本。

### 2.2 自适应大面板

状态栏展开后默认占当前可用高度的 75% 至 85%，目标值为 80%。顶部保留紧凑标题区，底部保留应用原生输入栏。面板支持拖动缩小和一键全屏。

头像下方至输入栏上方的区域全部供角色卡使用，不再为卡片固定 360dp 高度。用户选择的列表或详情模式、图片缩放和面板高度需要持久化，并提供恢复角色卡默认设置的入口。

### 2.3 自适应动效

角色开屏、角色切换和弹窗开启时保留完整动效。出现以下情况时自动减少或暂停非必要动画：

- 用户正在滚动或拖动面板。
- 渲染区域离屏、面板收起或应用进入后台。
- 系统启用减少动态效果。
- 应用处于省电或低电量约束状态。

恢复条件满足后允许继续动画，但不得重新播放会打断用户操作的长开场动画。

## 3. 架构

实现共享的自适应渲染宿主，供角色开场、状态栏和对话 HTML 共用。现有 `TavernConversationWebView` 与 `MarkdownWebView` 保留各自的容器职责，但通过同一组策略与协议运行角色卡内容。

### 3.1 RenderPolicy

负责根据渲染场景生成明确策略：

- 可用高度、最小高度、默认面板比例和全屏状态。
- 纵向滚动由 WebView 还是外层列表接管。
- 横向手势由卡片轮播还是外层页面接管。
- 是否允许运行脚本、请求远程资源和写入持久变量。
- 当前动效级别与生命周期状态。

策略必须由场景和权限生成，不允许在 WebView 内通过页面内容猜测宿主权限。

### 3.2 ViewportAdapter

负责可视区域和弹窗适配：

- 使用真实可用高度、`visualViewport` 和安全区信息，而不是依赖页面首次计算的 `vh`。
- 在 WebView 初始高度为零、旋转、键盘出现和面板拖动后重新计算视口。
- 检测可见的固定定位弹层是否被零 `max-height` 或视口边界裁切。
- 只在确认内容被裁切时写入最小修复样式；不得持续覆盖卡片主动设置的有效尺寸。
- 对尺寸和 DOM 变化合并到单个动画帧，并对上报设置变化阈值，避免观察器反馈循环。

通用修复通过行为条件判断，不绑定 `#set-m`、`.pv-b` 等单卡选择器。

### 3.3 MediaPipeline

统一处理角色卡远程媒体：

- 复用应用安全网络客户端和现有权限开关。
- 支持内存与磁盘缓存、请求超时、有限次数重试和取消。
- 检测图片 `complete`、自然尺寸和解码结果，不能以 DOM 中存在 `<img>` 作为成功标准。
- 加载期间显示与卡片背景协调的骨架占位。
- 单张图片失败时显示不破坏布局的重试入口；其他内容继续可用。
- URL、重定向、协议和内容类型继续接受安全校验，不开放通用文件访问或混合内容绕过。

### 3.4 TavernRuntime

继续提供 MVU、变量、宏、消息事件和酒馆兼容接口，并统一开场、状态栏与对话三条路径的能力边界。

- 每个渲染实例隔离脚本错误和生命周期。
- 会话变量由宿主作为权威数据源，页面通过快照和增量事件读取。
- 文档初始化一次；普通变量和状态变化使用增量事件更新，不整页重载。
- 脚本、宏注册、请求头和远程联网继续受现有 `TavernRuntimePermissions` 控制。
- 页面不得直接获得 Android JavaScript 接口密钥或绕过父级消息代理。

### 3.5 MotionController

统一控制宿主和卡片动画：

- `FULL`：进入、切换和明确交互反馈期间。
- `REDUCED`：页面稳定展示但仍在前台可见时，降低持续动画频率。
- `PAUSED`：滚动、离屏、后台、减少动态效果或省电约束期间。

通过宿主状态、页面可见性和 CSS 类/变量通知卡片。对于不支持该协议的卡片，宿主至少暂停自身装饰动画，并避免通过频繁重载间接重启动画。

### 3.6 FallbackRenderer

恢复顺序固定如下：

1. 保留最后一次成功画面。
2. 重试失败的单个媒体或运行步骤。
3. 在不重建整个文档的前提下重新初始化局部运行时。
4. 降级为静态安全 HTML。
5. 最终显示可复制的原始内容和明确错误摘要。

任何阶段都不得将状态标签、脚本源码或内部错误堆栈直接混入普通对话文本。

### 3.7 RenderDiagnostics

记录可用于本地诊断的结构化事件：

- 卡片/会话标识的脱敏引用。
- 文档初始化、增量更新和整页重载原因。
- 图片请求、重试和失败类型。
- 视口修复触发条件与修改范围。
- 脚本超时、异常和降级阶段。
- 高度上报、布局次数和动效状态变化。

诊断数据默认保留在本地，不记录角色卡正文、认证头或私人变量值。

## 4. 数据流

1. Kotlin 根据角色卡、会话、主题、权限和显示场景生成不可变 `RenderRequest`。
2. 宿主创建或复用对应渲染实例，首次加载完整文档。
3. 页面报告就绪后，宿主推送权威变量快照和当前消息上下文。
4. 后续状态、主题和消息变化通过有序增量事件发送；只有文档结构或权限边界变化才允许整页重载。
5. 页面以节流方式上报内容高度、弹窗状态、手势方向、媒体结果和运行异常。
6. 宿主更新面板布局、诊断信息或降级状态，不把瞬时页面状态写回角色卡源数据。

事件必须携带渲染实例代次或修订号。旧文档和旧请求的迟到回调必须被忽略。

## 5. 手势与滚动

- `ACTION_DOWN` 时，内部滚动场景先暂时禁止父容器截获。
- 达到方向阈值后锁定手势轴，单次触摸序列中不反复切换。
- 横向锁定后，完整序列留给角色卡轮播，确保页面收到结束或取消事件。
- 纵向锁定后，WebView 在可滚动区间内消费手势；到达顶部或底部并继续向外拖动时交还外层面板。
- 弹窗、范围滑杆和图片预览优先于页面轮播。
- 触摸取消时必须清理锁定状态，避免下一次手势继承旧方向。

普通聊天消息使用父列表连续滚动时，仍允许父容器接管；状态栏大面板和全屏卡片使用内部滚动策略。

## 6. 用户体验

- 状态栏标题区显示当前角色头像、名称、角色计数、设置和全屏按钮。
- 默认面板高度约为可用区域的 80%，用户可以拖动至约 50% 或全屏。
- 列表/详情、缩放和面板高度在会话间保留，同时提供恢复默认值。
- 角色切换使用短促、可取消的过渡；快速连续滑动只保留最后目标。
- 设置和预览弹窗始终限制在真实可视区域内，长内容由弹窗自身滚动。
- 图片骨架与失败重试保持卡片布局稳定，不显示破坏画面的英文浏览器占位文本。
- 原生输入栏保持现有视觉和功能，不在角色卡内复制第二套输入功能。

## 7. 错误处理与安全

- 单卡脚本异常不能影响其他消息、其他卡片或后续渲染实例。
- 超时任务必须可以被取消或丢弃，迟到结果不能覆盖新状态。
- 网络失败、HTTP 错误、内容类型错误和图片解码错误分别记录并允许有限重试。
- 卡片 HTML 继续运行在现有沙箱和权限边界内。
- 不启用 universal file access、任意 `content:` 读取或 mixed-content 绕过。
- 外部链接继续交由宿主确认和打开，页面不能直接发起不受控跳转。

## 8. 性能要求

- 普通变量更新不得重载完整文档。
- 视口、尺寸和 DOM 观察回调合并到单帧，并在数值未发生有效变化时停止传播。
- 离屏渲染实例暂停非必要动画、计时器和媒体活动。
- 列表滚动期间不执行装饰性布局修复；滚动结束后只运行一次确认。
- WebView 实例按明确生命周期创建和销毁，不因 Compose 无关重组重复加载。
- 真机空闲采样不得出现由宿主观察器造成的持续布局增长。

## 9. 验收与测试

### 9.1 自动测试

- RenderPolicy 的尺寸、权限、动效和手势所有权决策。
- ViewportAdapter 对零高度、有效自定义高度、旋转和弹窗裁切的判断。
- MediaPipeline 的协议校验、缓存、超时、重试、取消和内容类型处理。
- 运行时快照、增量更新、修订号和迟到回调丢弃。
- 触摸轴锁定、边界交接、取消清理和父列表模式回归。
- FallbackRenderer 的五级恢复顺序与原始内容保留。
- 动效状态在可见、滚动、后台和减少动态效果之间的转换。

### 9.2 Android 可见 WebView 测试

只运行明确过滤的可见 Activity 仪器测试，不使用会清除现有应用数据的全量连接测试命令。覆盖：

- 完整 HTML/CSS/脚本执行。
- 设置弹窗和长弹窗滚动。
- 远程图片成功、失败和重试占位。
- 增量变量更新不触发文档重载。
- 旋转与后台恢复后的视口和上下文重推。

### 9.3 华为真机验收

在 `XHD0223523008702` 上使用真实角色卡验证：

- 冷启动进入开场、状态栏和聊天，三处视觉与能力一致。
- 状态面板默认大面积展开、拖动缩小和一键全屏。
- 设置、列表/详情、滑杆、关闭和图片预览均可由真实触摸完成。
- 四角色连续横滑，角色计数、主题、图片和状态同步更新。
- 纵向长内容滚动与外层边界交接无明显卡顿。
- 所有远程图片 `complete=true`、自然尺寸大于零且肉眼可见。
- 网络断开后出现稳定占位，恢复网络后单图重试成功。
- 后台恢复、横竖屏切换和重复打开面板无空白或上下文丢失。
- logcat 无 FATAL/ANR，空闲状态无异常持续重排。

## 10. 实施边界

本轮只优化酒馆角色内容的统一渲染宿主及其状态面板体验，不重写应用原生聊天输入栏、不改变角色卡源格式、不新增不受权限控制的脚本或网络能力，也不借机重构无关页面。

由于当前工作区包含大量未提交实现，后续实施必须：

- 在写入前检查共享工作区是否被 `opencode.exe` 等外部代理占用。
- 保留现有用户改动，避免清理、硬重置或整树覆盖。
- 每项行为先建立失败测试，再做最小实现。
- 按任务分组验证，但提交时只暂存属于该任务的文件。
