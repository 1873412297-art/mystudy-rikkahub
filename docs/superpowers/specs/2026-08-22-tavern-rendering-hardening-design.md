# Tavern 沉浸式渲染强化设计

日期：2026-08-22  
状态：已获用户确认

## 1. 目标

在不牺牲 SillyTavern 角色卡 HTML、CSS、JavaScript 和运行时 API 兼容性的前提下，同时强化三类体验：

1. 完整兼容：远程人物图、CSS 背景图、长 HTML、动态高度和失败恢复可靠工作。
2. 视觉效果：开场卡充分利用头像下方宽度，加载和切换过程自然、稳定、不闪白。
3. 流畅性能：保持单一纵向滚动所有权，减少 iframe 重排、重复下载和无效高度更新。

## 2. 现状与约束

- Android 沉浸式酒馆对话使用 `TavernConversationWebView` 和 `tavern-conversation.html`，不是普通消息的 `MarkdownWebView`。
- 角色卡开场可能包含任意长的 HTML、远程 `<img>`、CSS `background-image`、脚本和动态 DOM。
- 外层对话 WebView 必须继续拥有纵向滚动；内层 iframe 不建立第二个滚动手势所有者。
- 脚本权限、网络权限和 iframe 沙箱边界保持不变。
- 不引入公共第三方图片代理，不把角色卡私有 URL 发送到额外服务。
- 真机验证不得使用会卸载目标 Debug 包并清除应用数据的测试工作流。

## 3. 推荐架构：分层增强

### 3.1 展示层

开场消息采用紧凑顶部信息区：头像和角色名只占首行；正文、HTML iframe 和状态内容从下一行开始使用消息区域全宽。左右开场按钮使用覆盖式定位，不参与正文宽度计算。按钮默认降低视觉权重，在触摸、键盘聚焦或切换进行时恢复清晰度。

HTML iframe 报告完整文档高度，外层容器不裁切。宿主对高度值执行有效性检查、绝对上限和去抖；只有超过小幅阈值的变化才写回布局，避免图片解码和字体加载造成连续抖动。

### 3.2 媒体层

新增职责单一的远程媒体加载组件，由沉浸式 WebView 的资源请求入口调用：

- 只处理 `http` 和 `https` 图片请求，包括 `<img>` 与 CSS 背景图产生的请求。
- 使用应用现有安全网络客户端和代理配置，设置连接、读取和总时限。
- 校验响应类型、响应长度和最终协议；拒绝非图片响应及超限资源。
- 将成功结果写入有界磁盘缓存，并按 URL 与响应校验信息复用。
- 网络失败时可使用仍有效的缓存；没有缓存时回退给 iframe 内的单一失败占位。
- 同一 URL 的并发请求合并，避免开场候选预载产生重复下载。

iframe 内把 `loading="lazy"` 图片提升为主动加载，因为 iframe 自身不负责滚动。媒体成功时渐显；失败时隐藏浏览器原生破图图标，只生成一条包含原始 `alt` 文本的中文重试控件。重试复用原始 URL，不叠加占位节点。

### 3.3 生命周期与性能层

- 选中的开场候选保持完整渲染；邻近候选只保留轻量预备状态，不同时执行多份长卡脚本。
- 开场切换优先复用已完成的媒体缓存和解析结果，避免白屏。
- 高度消息通过动画帧合并，并增加最小变化阈值；最终稳定高度仍保证同步。
- 图片加载只触发 iframe 自身尺寸报告，不触发整条消息或整个对话文档重建。
- 缓存采用明确的容量和条目上限，超限按最近最少使用策略回收。
- 页面销毁时取消未完成请求、释放观察器和事件监听器。

## 4. 数据流

1. 角色卡开场进入 `TavernConversationSnapshot`，HTML 由对话模板写入沙箱 iframe。
2. iframe 启动脚本将卡内懒加载图片转为主动加载并监听媒体成功、失败和尺寸变化。
3. WebView 收到远程图片或背景图请求，交给受控媒体加载组件。
4. 加载组件依次检查内存中的合并请求、磁盘缓存和网络，并向 WebView 返回经过校验的图片响应。
5. 图片解码完成后 iframe 渐显媒体并报告新高度。
6. 外层对高度消息去抖、限幅和阈值过滤，再更新 iframe 高度；对话 WebView继续承担唯一纵向滚动。

## 5. 错误处理

- URL 非法、协议不允许、权限关闭：不发起网络请求，进入本地失败占位。
- DNS、TLS、连接或读取失败：优先使用有效缓存，否则显示一次可重试占位。
- 非图片响应或资源过大：终止读取，不写缓存，显示失败占位。
- 图片加载后动态改变尺寸：合并高度变化，最终同步稳定高度。
- 卡片脚本异常：错误限制在当前 iframe，不影响开场切换、原生输入栏或其他消息。
- 缓存损坏：删除单个损坏条目并尝试网络，不清空整个缓存。

## 6. 安全边界

- 网络加载继续受角色卡 `networkAllowed` 和现有脚本权限控制。
- 不增加 iframe 的可信原生能力，不向卡片暴露文件路径、认证信息或宿主网络客户端。
- 限制重定向次数、响应大小、MIME 类型及允许协议。
- 不执行图片响应内容，不允许图片请求转为本地文件或其他高权限协议。

## 7. 测试与验收

### 7.1 自动测试

- 文档契约测试：全宽开场布局、覆盖式切换按钮、完整高度、主动图片加载、单一失败占位。
- 媒体加载器单元测试：权限门控、缓存命中、并发合并、超时、重定向、MIME/大小拒绝和失败回退。
- WebView 定向仪器测试：远程 `<img>` 与 CSS 背景图可见、失败重试不重复、动态高度最终稳定。
- 回归验证：`testDebugUnitTest`、`compileDebugKotlin`、`assembleDebug`。

### 7.2 真机验收

- 角色卡正文宽度接近消息可用区域全宽，头像下方不留长期空列。
- 超过四屏的卡片首尾均可到达，外层滚动连续且无 iframe 内部抢手势。
- 网络可达时人物图和背景图可见；断网时每个媒体只有一个带名称的可重试占位。
- 连续切换多个开场不闪白、不意外回到顶部，切换动画尊重“减少动态效果”设置。
- 安装后应用正常启动，logcat 无 FATAL；代理设置在验收后恢复原值。

## 8. 非目标

- 不把任意酒馆 HTML 重写成原生 Compose 组件。
- 不引入公共图片中转服务或绕过用户网络策略。
- 不更换应用原生输入栏、顶部栏或导航结构。
- 不扩大角色卡脚本权限。
